# 数据 API 发布契约

更新：2026-09-05，Flyway V28。对应剩余计划 V2-09A；实际验证见 [验收基线](v2.0-acceptance-baseline.md)。

## 草稿与线上版本

`data_service_definition` 保存可编辑草稿、并发修订号 `revision` 和当前发布指针 `publishedVersionId`。`data_service_version` 保存只追加的发布记录；编辑草稿不会增加发布版本，也不会改变开放接口实际执行的 SQL、参数或运行限制。

发布快照包含服务编码、名称与说明、创建者执行身份、SQL、参数定义、Catalog／Database、最大行数、超时、每分钟调用上限、结果列元数据、直接依赖、草稿修订、发布人、来源与发布说明。服务编码创建后不可修改。

发布在同一数据库事务内锁定定义行，重新校验并生成版本，再切换当前指针。同一 `expectedRevision` 的并发发布只能有一个成功。调用取得一次当前发布快照后全程沿用它；随后发生发布或下线不会把已取得版本的在途查询切换为其他 SQL。

回退会用所选历史快照重新做当前权限和结构校验，兼容当前线上契约后追加一个新版本，记录 `origin=rollback` 与 `sourceVersionId`。它保留现有草稿。下线保留发布指针与历史，重新上线仍需发布或回退校验；线上服务不能直接删除，下线删除后历史证据仍保留。

## 管理接口与并发处理

下表为后端路径；经 Nginx 调用时加 `/api/v1` 前缀。

| 接口 | 行为 |
| --- | --- |
| `GET /data-services/{id}` | 读取草稿、`revision`、发布指针、`hasDraftChanges`、`manageable` |
| `PUT /data-services/{id}` | 保存完整草稿，请求必须携带读取到的 `expectedRevision` |
| `GET /data-services/{id}/published` | 读取当前指针引用的快照；服务下线后仍可读取 |
| `GET /data-services/{id}/versions` | 按版本号倒序返回当前用户有权访问的历史 |
| `POST /data-services/{id}/preview` | 预检已保存草稿，不创建发布记录 |
| `POST /data-services/{id}/publish?published=true` | 重新预检并发布草稿；`published=false` 为下线 |
| `POST /data-services/{id}/rollback/{versionId}` | 校验历史定义后追加新发布记录 |

预览、发布、下线与回退请求使用 `{"expectedRevision": 3, "changeSummary": "变更说明"}`，其中说明可省略。修订过期返回 HTTP 409，缺失修订返回 HTTP 400；客户端应刷新、保留并核对自己的修改后重新操作，不能自动覆盖他人更新。**原来无请求体的发布／下线调用需要升级**，旧的草稿更新调用也需增加修订号。

预览返回 `publishable`、变更项、阻断原因、结果列、直接依赖和 `compatibilityBasis`。预览通过不预留发布资格；正式发布再次检查当前权限与结构。

## 参数和结果兼容性

发布只接受受支持 SQL 解析子集中的 SELECT。参数沿用类型化值渲染，不能用参数替换表名或 SQL 片段。使用默认值或代表值执行 `SELECT * FROM (<SQL>) AS api_contract LIMIT 0` 获取元数据，设置 15 秒语句超时和 Doris 内存限制；不读取业务结果行。参数直接用于输出表达式时应显式 `CAST`，避免不同值改变结果类型。

同一服务编码下不允许删除或改变参数类型、把可选参数改成必填、移除必填参数的有效默认值，或新增无有效默认值的必填参数。允许修改有效默认值，但仍需显式发布并说明行为变化。

结果列数量、名称、顺序、类型、精度和小数位必须保持一致；原本不允许 NULL 的列不能变为允许 NULL。重复输出列名在预检时拒绝。每次调用也检查实际 ResultSet 元数据，发生不兼容漂移时拒绝返回业务结果。破坏性变更需使用新的服务编码并迁移调用方；当前不提供自动调用方迁移。

兼容性校验覆盖输入和结果结构，不能证明 SQL 业务语义、默认值变化或运行上限变化对所有消费者无影响。

## 权限与证据

管理操作要求对应功能权限，编辑／发布／回退／下线／删除还要求创建者或管理员身份。非管理员读取定义时同时检查草稿和当前快照的范围；历史与日志按各自执行快照鉴权，不随草稿改到其他表而转移访问权。管理员可读取并修复失效定义，但正式发布仍核验发布人及创建者当前 SQL／View 权限。

开放调用依次校验应用凭证、有效期和授权，执行人仍是快照记录的创建者。创建者必须处于启用状态且仍具有 `data-service:manage`，执行 SQL 时递归检查受管 View 与底层对象的当前权限和结构。停用账号、撤销功能权限或数据范围会阻断后续调用。

响应增加 `versionId`、`apiVersion`、`contractOrigin`；已取得快照的成功与失败日志记录实际 `versionId`、`apiVersion`、`executionUserId`。在取得快照前失败的请求没有可认定的执行版本。没有版本依据的旧日志只对管理员显示。

资产上下文和全局已发布服务统计从发布快照读取 SQL、环境及名称。资产消费关系携带发布版本 ID／版本号，证据标记为 `published_service_sql_ast`；未发布的草稿不会替换线上消费关系。

## V27 → V28 升级

迁移只捕获升级时处于 published／offline 状态的当前定义，标记 `legacy_capture`，保留当时的计数作为版本号并设置发布指针。旧实现编辑后可能已改变在线 SQL，因此不能把旧计数解释成完整历史。迁移不猜测历史发布人，不补造结果列／依赖契约，也不回填调用日志的版本。

升级捕获版本继续按旧定义调用，暂不执行未知的结果列契约检查。再次发布时同时探测旧定义当前结构与候选草稿，`compatibilityBasis=legacy_current_schema` 明确表示比较基于当前结构；新版本从此保存完整契约。旧 SQL 已失效时不能凭空补证，可下线并用新服务编码迁移。

部署前备份管理库并停止旧后端写入，单控制面启动新后端执行 Flyway，再部署匹配的前端。先用专用旧 API 验证升级前后返回一致，再验证草稿隔离、重发布与回退。V28 没有自动向下迁移；需要恢复时应停止写入，在隔离库中恢复备份并核验，再按已确认的数据恢复窗口切换，不能在运行中的库上直接删除新表或降级。此次完成了备份及真实升级，完整备份恢复演练仍由 V2-11B 验收。

## 支持边界

- 当前验收范围为本地单控制面、MySQL 管理库、真实 Doris 与受管普通 View。频率限制和查询协调仍在进程内，多副本不在本次认证范围。
- 快照冻结 API 定义和直接依赖名称，不固定 Paimon 物理快照、基础表数据或 View 的发布版本；符合结构的底层数据变化仍可能影响返回值。
- 本次不增加可用产出／业务窗口／质量豁免消费门禁，后续由 V2-09B 实施。参数和结果契约不能替代质量交付证据。
- 页面代码、类型检查与生产构建已完成；已补验创建、编辑草稿隔离、预检、发布、版本详情、回退保留草稿和不兼容列变更拒绝，覆盖 1024／1280／1440 宽度。回退失败弹窗尚未单独做浏览器负向验收，详见 [页面记录](validation/v30-browser-smoke.json)。
