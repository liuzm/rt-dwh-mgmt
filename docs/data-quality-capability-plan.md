## 本轮检测契约

- `checkScope=full_table` 检查全部当前数据；`business_window` 要求 `timeColumn`，使用业务本地日期的 `[当天 00:00, 次日 00:00)`。时间字段应为 DATE / DATETIME；不隐式进行时区换算。时间字段为 NULL 的行不在日期窗口内，需另配全表空值率规则发现。
- 手动检查和预览传 `businessDate=YYYY-MM-DD`。未指定窗口日期的窗口规则留下 error 证据，不回退为全表。页面默认前一日。全局定时检查也使用配置时区当天的前一日（`QUALITY_SCHEDULE_TIMEZONE` 默认 `Asia/Shanghai`，避免 Docker UTC 跨日偏差）；独立规则调度尚未提供。
- 产出检查读取发布时冻结的规则与实例窗口；修改当前规则不会改变已发布任务。新窗口配置应用到后续产出时，需要重新发布任务。blocked 重检继续使用原版本及同一窗口，追加证据，不生成新产出。
- `emptyPolicy=fail` 为默认：范围内零行时 failed，即使比率为 0；`allow` 允许空数据，仍判断阈值，例如行数下限 10 在空表中仍失败。旧规则迁移后默认 fail；历史运行结果不改写。旧发布 JSON 未含此字段时按 fail 处理。
- 空值率：NULL 行数 / 总行数，≤ 阈值；唯一率：非空去重值数 / 总行数，≥ 阈值。唯一率的异常计数为总行数减非空去重数，含 NULL 和重复的额外行，不等于所有重复组涉及行数。
- 越界率：表达式为 false 或 NULL 的行数 / 总行数，≤ 阈值。若要允许 NULL，需在表达式中明确 `field IS NULL OR ...`。
- 行数下限：总行数 ≥ 阈值；无行级异常计数，记录为 NULL。所有指标与行数使用一次 SQL 聚合，避免两次查询读取不同数据。
- 检测 SQL、目标完整名称、规则版本、窗口、空数据策略、行数与结果共同保存。SQL 预览只生成并验证权限与 View 依赖，不执行检测，不保存规则，也不创建运行或告警；它不是完整的 Doris EXPLAIN/字段存在性验证。
- 告警去重、运行先后顺序比较及自动恢复均按 `ruleId + scopeKey`。某日通过不能恢复另一日失败。人工确认只关闭通知处置状态，不能将检测或产出门禁改为通过。规则编辑、停用、删除仍以 suppressed 关闭旧告警。
- 历史运行/告警按当时的目标表鉴权，不能通过修改当前规则目标继承其他资产历史权限；删除规则后仍保留可见的历史。旧单段目标缺少不可变库名证据，按拒绝可见处理，不能信任从当前规则推断出的历史分层。
- 首屏覆盖率/通过率按所选日期与当前规则版本统计，全表规则显示最新检测；趋势与近 24 小时统计按执行时间。资产入口只筛选列表，顶部指标和“全部可访问启用规则”操作覆盖当前账号的全部可见规则。

## API

- 规则创建/更新增加 `checkScope`、`timeColumn`、`emptyPolicy`。
- `POST /quality/preview?businessDate=2026-09-04`：请求体同规则输入，返回 SQL / scopeKey / window / emptyPolicy。
- `POST /quality/rules/{id}/run?businessDate=2026-09-04`，`POST /quality/run-check/all?businessDate=2026-09-04`。
- `GET /quality/overview?businessDate=2026-09-04` 返回对应日期窗口及全表规则的最新记录。
- `GET /quality/runs` 的历史结果包含 `checkedRows`、`violationRows`、`windowStart/End`、`scopeKey` 等证据。

## 边界

全表规则仍可作为整体约束，但全表通过不能证明某个补数窗口的完整性，需显式配置窗口规则。检测读取的是执行当时的 Doris / Paimon 数据，未固定 Paimon snapshot；迟到写入可能改变重检结果。blocked 是管理面交付阻断，不撤回已经写入的数据。责任人通知、SLA 迟到事件、审批豁免、异步检测、完整模板库仍属后续阶段。

迁移使用 Flyway V27，部署前备份本地管理库；不删除用户数据。验证与验收记录见开发进度文档。
