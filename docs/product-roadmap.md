> 2026-09-05 更新：本文保留早期路线图，其中发布契约、交付门禁、维护终态、资产、普通 View 和窗口质量等条目已在后续迭代中推进。当前能力与边界请以 [产品能力全景](product-capability-map.md) 和 [2.0 实施进度](v2.0-implementation-progress.md) 为准。下文历史条目的“已完成／核心完成”不代表完成升级恢复或多副本生产认证，历史缺口也不应直接当作当前待办。

## 判断标准

- **已完成**：页面、API、执行链路、状态回写和异常处理可以形成闭环，并有测试或可重复验证方式。
- **部分完成**：已经具备数据模型、页面或控制面，但仍依赖人工操作、外部脚本或未实现的执行器。
- **未开始**：当前只有字段、概念或规划，没有可用入口和运行链路。
- **P0**：影响当前版本完整交付或核心承诺，需要优先完成。
- **P1**：影响生产可用性和规模化使用，应在下一阶段完成。
- **P2**：提升治理深度和平台化程度，可在核心链路稳定后推进。

## P0：完成核心交付闭环

### 0. 核心执行模型与湖仓目录收敛

**当前状态：已完成。** 任务新增 `executionMode`，持续任务只走 Flink Job 生命周期，周期任务只走版本、DAG、Cron、补数和实例生命周期；跨模式操作由服务端拒绝。周期实例创建时固定保存 `definitionVersionId`，Runner 从不可变版本快照执行，编辑草稿不会改变线上已发布版本。Paimon 不再作为普通数据源重复创建或被任务选择，而是在系统设置中作为平台级 Catalog／Warehouse 统一管理。

同时，Catalog／Database／Table 数据范围已扩展到任务、产出资源、质量、报表和治理中心聚合，模块入口与实际执行使用同一服务端授权口径。

### 1. 一键部署与验收

**当前状态：已完成。** Compose 已包含 MySQL、PostgreSQL、Flink、SQL Gateway、Doris、后端、前端，并通过 Profile 提供监控组件；所有 Paimon 访问方使用同一 Warehouse 挂载。

已交付：

- 恢复 Flink JobManager、TaskManager、SQL Gateway、Backend 和 Frontend 服务；
- 使用 Compose Profile 区分核心组件、可选数据源和监控组件；
- 统一宿主机与容器内的 Paimon Warehouse、JDBC Catalog 和网络地址；
- 增加依赖健康检查与合理的启动顺序；
- 提供环境模板、启动命令和非破坏性状态检查；
- 增加一条从 MySQL 测试表到 Paimon，再由 Doris 查询的冒烟验证。

完成标准：在全新环境执行一条启动命令后，能够登录平台、创建 CDC 任务、产生一条增量数据，并在 Doris 查询结果中看到该数据。

### 2. 告警规则自动执行

**当前状态：已完成核心闭环。** 任务失败、数据延迟和质量异常规则会定时评估，支持对象级去重、自动恢复、恢复通知和通知状态记录，也可以在页面手动触发评估。

已交付：

- 为任务失败、数据延迟和质量异常建立规则评估器；
- 将规则中的阈值／表达式转换为明确、可校验的结构化配置；
- 增加触发去重、恢复通知和发送结果记录；
- 避免相同故障在每个监控周期重复发送。

完成标准：配置一条延迟阈值规则后，系统能够自动触发一次告警、记录通知结果，并在指标恢复后发送恢复通知。

### 3. 周期 ETL 执行与数据交付

**当前状态：已有执行基础，交付语义仍需补齐。** DAG、版本、补数、依赖释放与内置 Flink SQL Runner 已有实现；外部 Runner 仍可使用同一套领取和回写协议。但当前依赖按执行 success 放行，未绑定具体可用产出；产出与依赖也未包含在任务发布快照中。下一版需将完整发布契约、业务窗口和质量门禁贯通。

此处不代表 Flink 原生 Materialized Table 已完成支持：该场景仍需独立的环境预检、Catalog Store、刷新所有权和生命周期适配。普通 View 与 Doris 异步物化视图亦不能由现有任务入口推定已支持。

已交付：

- 至少提供一种官方 Runner，例如 Flink SQL Runner 或 Doris SQL Runner；
- 把任务 SQL、业务日期、运行参数和上游产出传递给 Runner；
- 回传 Job ID、日志、开始／结束时间、结果和失败原因；
- 为实例增加超时、租约、心跳、取消、重试退避和失败转人工；
- 使用幂等键防止同一业务日期重复执行或重复回写。

完成标准：创建两级 DAG 并发起补数后，平台可自动执行上游和下游任务，且失败实例能够按策略重试并保留完整日志。

### 4. 核心链路自动化回归

**当前状态：已完成首版。** `scripts/smoke-cdc-paimon-doris.sh` 会创建隔离源表和临时配置、启动 CDC、写入增量事件，并通过 Doris 查询 Paimon 断言结果。

已交付：

- 准备隔离的 MySQL 源表和 Paimon 测试 Catalog；
- 自动创建 CDC Job，并验证 insert 增量变更；
- 校验 Flink Job 启动和 Doris 最终查询结果；
- 测试数据、Job 和 Catalog 使用唯一命名并可安全清理。

完成标准：CI 或独立验收脚本能够稳定输出端到端通过结果，不依赖人工进入 Flink、Doris 或数据库排查。

## P1：达到生产可用

### 5. PostgreSQL CDC 完整支持

**当前状态：核心闭环已完成。** 已支持 PostgreSQL 数据源配置、Schema 探测和 CDC SQL 生成；默认 Flink 镜像已打包 Connector，Compose 已启用 logical replication。启动前会检查 `wal_level`、复制权限、Publication 权限和 Slot 容量，每个任务/表使用稳定 Slot 与 Publication 名称，任务页支持安全清理，删除任务时自动回收。

待完成：扩展数组、区间等 PostgreSQL 特有类型兼容矩阵，并把 PostgreSQL 增量场景纳入独立端到端回归。

### 6. 查询资源与成本治理

**当前状态：核心闭环已完成。** 已具备超时、返回行数、并发限制、公平短时排队、Workload Group、成功率和 P95；通过 Doris Trace ID/Statistics API 采集真实 Query ID、扫描行数、扫描字节、CPU、峰值内存、本地/远端读取量和缓存写入量，并在结果与历史中展示。用户可以按本人查询记录打开 Doris 完整 Query Profile。平台会记录排队时间，按扫描量、CPU 和峰值内存计算成本分，标记软预算超限并给出个人高成本查询 Top 10。

待完成：慢查询自动归因，以及管理员视角的跨用户／报表成本运营排行。

### 7. 报表调度与分发

**当前状态：核心闭环已完成。** 已支持报表编辑、发布、看板展示、CSV 导出、六段 Cron 与时区配置、定时/手动运行、结果快照留存、失败重试和运行历史；可声明 string、number、boolean、date、datetime 和 stringList 参数，通过 `{{parameter_name}}` 安全渲染值参数，交互查询与调度参数共用服务端白名单和类型校验；可按成功/失败条件向订阅邮箱、钉钉或企业微信分发摘要，并记录分发结果。

待完成：带附件、签名链接和品牌样式的丰富分发模板。

### 8. 用户与权限管理

**当前状态：核心闭环已完成。** 已有 JWT、接口权限码和管理页面；管理员可创建/编辑/启停用户、重置密码、分配角色，并维护自定义角色、接口权限及 Catalog／Database／Table 通配范围，内置角色受到保护。数据范围同时作用于 Catalog 树和实际查询，服务端使用 SQL AST 检查 CTE、JOIN 中的每张物理表；自定义角色无范围时默认拒绝，ADMIN 旁路。

后续增强：把平台范围策略同步为 Doris 原生用户／角色授权，形成数据库侧纵深防御。

### 9. Kubernetes 生产部署

**当前状态：核心模板已完成。** Chart 已包含 Helper、Backend/Frontend Service 与 Deployment、Nginx ConfigMap、Secret 引用、ServiceAccount、PDB、Ingress、探针和容器安全上下文；默认 values 不再保存明文密码，并通过 Helm 3.16 lint。

部署模式：Chart 只部署管理平台，MySQL、Flink、Doris 和共享 Paimon Warehouse 由生产集群或对应 Operator 提供。待完成最小 Kubernetes 集群安装与升级/回滚验收。

### 10. 工作流运行韧性

**当前状态：已完成。** 实例领取使用数据库悲观锁并按 `next_retry_at` 领取；内置 Runner 和外部执行器协议均支持 Job ID、租约、心跳、超时回收、指数退避、取消和人工重跑。

后续增强：增加批次级暂停／取消、运行日志聚合和更细粒度的重试策略。

### 11. 周期数据资源产出

**当前状态：已完成首版闭环。** 非 CDC 任务发布版本后，可以配置六段 Cron、时区、业务日期偏移和 JSON 运行参数。平台自动创建运行实例，并维护下次／上次触发时间。

任务可声明一个或多个产出数据资源，维护 Catalog、Database、Table、分层、负责人、说明和 SLA。实例成功后写入独立产出记录；启用质量门禁时，会立即执行命中目标表的质量规则，失败产出标记为 `blocked`，通过后才更新最近产出时间并登记为数仓资产。调整或移除资源配置采用停用方式，历史产出不会丢失。

优先补齐：blocked 产出须阻断相应数据依赖，并明确检测业务窗口及产出版本；当前管理库标记不等于阻止任意 SQL 读取已写入的物理表。随后增加补发策略、错过调度的可选追赶模式，以及 SLA 逾期自动告警与运营看板。

### 12. 外部数据接口

**当前状态：已完成首版闭环。** 用户可以把经过只读校验的 Doris SQL 模板发布为 `/api/v1/open/data/{serviceCode}`，使用与报表相同的类型化参数渲染，限制最大行数和超时，并继续执行服务创建人的 Catalog／Database／Table 数据范围策略。

管理端支持创建调用应用、一次性签发或轮换 AppSecret、启停应用、按服务授权；开放接口使用 AppKey／AppSecret 鉴权，提供进程内每应用每服务限流，并记录调用状态、HTTP 状态、来源 IP、返回行数、耗时和错误。

后续增强：生产多副本场景使用 Redis／网关实现分布式限流，并根据安全等级增加 HMAC 请求签名、时间戳防重放、IP 白名单或 OAuth2 Client Credentials。

## P2：增强治理与平台化

### 13. 列级治理与安全

当前敏感级别只维护在表级。后续需要列级业务描述、列级血缘、敏感字段识别、脱敏策略，以及 Doris 行权限和列权限映射。

### 14. 指标口径管理

当前报表和数据接口直接使用 SQL 模板，缺少统一指标口径。后续需要指标定义、维度、口径版本、负责人、消费方和变更影响分析。

### 15. SLA 与成本运营

公共能力治理中心已经按当前账号的数据范围汇总周期数据资源的 SLA 逾期风险，并关联负责人、任务和严重级别；同时展示质量、组件健康、告警及失败变更健康分。后续仍需要数据新鲜度趋势、任务成功率、质量通过率、查询资源、存储增长、容量预测、值班升级和 SLA 违约历史看板。

### 16. 变更审批与发布

当前已记录写操作审计，但没有审批流程。后续可对数据源、生产任务、质量规则、权限和高风险维护操作增加审批、发布前检查、灰度与回滚。

## 建议迭代顺序

以 [2.0 迭代规划](v2.0-product-iteration-plan.md) 为新的排序依据：

1. 先修复门禁依赖、维护终态和跨模块权限等当前交付缺口。
2. 冻结完整发布契约，建立计算执行与数据交付的独立状态和可追踪关系。
3. 收敛资产入口，完善 Schema 变更、普通 View 和紧凑连续的页面流程。
4. 完成 Flink 伸缩、Paimon 生命周期、质量／SLA 与 API 发布契约。
5. 用真实链路、升级迁移、故障和浏览器测试完成 GA 验收；原生物化与自动伸缩按 Beta 准入。

列级治理、指标平台、通用审批和新增接入引擎后移，不与 2.0 核心交付同时扩张。

## 不纳入当前范围

- 自研替代 Flink、Paimon 或 Doris 的计算与存储内核；
- 在 RT-DWH 中实现通用 BI 自助分析平台；
- 在单机 Compose 中模拟生产级 Flink／Doris 多节点高可用；
- 同时支持所有 CDC 数据源和所有湖仓格式。

这些能力应通过稳定的 Connector、Runner 和外部系统集成完成，而不是继续扩大控制面的内核范围。
