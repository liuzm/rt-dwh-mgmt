### V2-01：可靠性与权限修复

代码已实现，自动化回归通过；真实 CDC／Doris 查询、Compact 成功与失败、Gateway 断连恢复及双角色 HTTP 范围检查已通过。超时路径使用单条测试记录的时间注入验证。

- 旧依赖兼容路径检查同业务日期最新上游实例及其实际产出。上游执行成功但产出 blocked、缺少应有产出、最新执行尚未成功时不放行；移除草稿产出不会消除已记录的 blocked。V24 新实例改用下述明确绑定。
- 维护改为持久化的 SESSION → CATALOG → USE → CALL → JOB（如有）流程。使用 Gateway 的 sessionHandle／operationHandle，只有确定执行终态后才关闭会话；返回 Job ID 时继续核对 Flink Job。
- Gateway 中断、提交回包丢失记录 unknown；观测超时记录 timed_out 并继续协调。没有操作句柄的模糊提交不会自动重试，避免重复清理。历史 running 记录迁移为 unknown，不伪造成功。
- 每个维护会话初始化平台 Paimon JDBC Catalog。Compact 使用命名 compact_strategy 参数，修复把策略误放到分区参数的问题，依据 [Paimon 2.0 Procedures](https://paimon.apache.org/docs/2.0/flink/procedures/)。
- 血缘按照用户可访问任务和表构建；持久化边、关键词扩展、SQL 注释解析不会重新引入无权表。
- 数据服务列表、修改、发布、删除、授权及日志增加数据范围检查。调用应用仅管理员或创建者可管理，包括密钥轮换、停用、授权和撤销。
- 表详情、字段、快照、注释、治理编辑、维护及日志入口补齐对象范围检查。批量维护先校验整个范围，再开始执行；全局元数据同步限管理员。
- 维护页面显示待人工执行、待协调、超时协调和真实终态，周期刷新日志；受理提示不宣称执行完成。

### V2-02：类型化参数、调度修订、运行配置与权限审计

- 新发布任务固定 `parameterSchemaJson`，支持 string／integer／number／boolean／date／datetime、必填与默认值。创建补数／调度实例时按发布契约校验并落下实际参数，默认值不再随草稿漂移。
- `${name}` 只渲染完整值；兼容 `'${bizdate}'` 与旧版本的标量值写法，拒绝标识符拼接、片段替换、错误类型和未知参数，参数值不递归展开。旧任务没有类型定义时，重新发布前需要补齐参数契约。已发布旧实例保留兼容读取，但同样使用安全字面量渲染。
- 新增 `task_schedule_revision`，保存 Cron、时区、业务日期偏移、参数、启用状态、修改人及动作。每次配置／删除保留记录，实例固定 `scheduleRevisionId` 与 `scheduledAt`；执行身份来自对应修订的修改人。历史调度首次触发时只采用当时可观察配置，不伪造过去的修订。
- 新增版本内运行配置 JSON 与指纹，涵盖 Gateway／Flink／Doris 端点、Paimon Catalog／Warehouse 及受控凭证引用。执行前检查当前配置一致性，地址或 Warehouse 漂移需重新发布；凭证轮换通过引用解析，明文密码不进入新发布快照。
- 运行配置指纹覆盖代码列举的配置项与 JDBC 安全选项；不代表已认证镜像 digest、所有任意连接参数或引擎能力。跨环境自动映射仍未提供。
- 新增独立事务权限检查记录，持久化执行身份、发布版本、实例、动作、结果与时间；在真正提交前对渲染后的 SQL 和冻结产出重验范围。界面增加参数契约、调度历史和权限检查入口。
- Savepoint 联调修复：使用 Flink 的 `request-id`、`operation.location`、`operation.failure-cause`，区分请求完成与执行失败；停止作业不会抢先清除保存点句柄，手动保存点仍保持运行。不再在不确定的停止响应后自动调用第二个端点，接口依据 [Flink 2.2 REST API](https://nightlies.apache.org/flink/flink-docs-release-2.2/docs/ops/rest_api/)。

### V2-03：交付状态、依赖绑定、补数策略与执行尝试

核心控制面已实现并完成本地 HTTP／Flink 验证；提交后安全重放及物理数据版本隔离仍未认证。

- 计算 success 后进入独立的 deliveryStatus=checking，由交付协调器执行冻结质量规则并登记 available／blocked。暂时性持久化故障保留计算成功，等待交付恢复；规则失败和检测异常保留明确原因。
- 新实例固定按日业务窗口 `[businessDate, 次日)`。产出记录增加定义版本、attempt、窗口、质量批次及检测时间，不用历史空字段推断可信证据。
- 数据依赖显式指定上游产出，按版本、窗口及 productionId 绑定；纯控制依赖显式选择 execution_success。已绑定的产出不随最新记录漂移，领取和提交前再次校验条件，提交时重验上游版本权限。
- 补数默认 batch_only，递归创建同批上游祖先任务；显式 reuse_available 才使用同版本、同窗口的已有可用产出。支持上游参数映射并限制批次规模，创建失败整体回滚。
- 每次领取产生独立 attempt，持久化执行器、提交意图、Job ID、状态和错误。提交意图必须先于外部调用；旧 attempt、错误执行器、未登记意图的 Job 绑定均被拒绝。历史尝试和 Job ID 保留。
- 完成回调使用实例行锁，并刷新请求内可能已加载的实体；重复完成保持相同终态和完成时间。交付登记在独立事务内通过行锁和唯一键去重，回调不会重复执行质量检测。
- 仅确定没有提交意图／Job ID 的失败尝试可重试；重新领取创建新 attempt。提交结果不明、Job 丢失及提交后租约过期保留 unknown，不自动重放，也不能把不明写入直接标为已取消。租约回收加锁后再次核对当前心跳。
- blocked 实例可按原规则重检，复用 productionId 并追加检测历史。重检不把检测时间作为新的产出时间，不覆盖更晚的最近产出实例。
- 页面展示计算／交付状态、执行尝试、依赖绑定、补数策略和检测历史；首次产出被阻断时仍可查看记录。日期数组按业务日期格式显示。

接口接入与兼容行为见 [周期执行与数据交付契约](workflow-execution-contract.md)。

### V2-05：普通 Doris View（首个子包）

已实现受控 DDL、草稿/发布版本隔离、递归依赖权限和统一资产入口。该子包保守固定已发布 View 的输出列与直接依赖集合，尚未达到 V2-05 全量 GA 范围。

- Flyway V26 将资产地址唯一键扩展为 Catalog/Database/Name；Doris View 与 Paimon 表共享 UUID 资产目录，旧 Paimon 元数据和维护接口按类型隔离。
- View 位于 `internal.rtdwh_views`。定义只接受可完整解析的 SELECT 子集和三段依赖；首次发布不覆盖已有物理对象，后续发布核对冻结 Doris 定义、字段契约与当前依赖权限。
- 发布意图先提交管理库，再执行 CREATE/ALTER。DDL 结果不明保留 applying/unknown 并阻断后续使用，不自动重复提交。发布历史保存 SQL、依赖、输出列和发布者；草稿修改不改变线上版本。
- 即席查询、报表和 API 均在 Doris 专用校验入口展开托管 View，检查每层及基础表权限、缺失/循环/定义漂移/字段变化，限制展开规模。管理员同样须通过定义完整性检查；工作台保持只读。
- 已发布 View 的列契约或直接依赖集合变化被预览及发布接口同时阻止，需要使用新名称迁移。资产上下游关系加入已发布 View 的直接依赖；完整传递影响分析、变更迁移和未知 DDL 的人工接管入口仍待后续子包。
- 公共检索按资产实际 Catalog 过滤，报表与服务检索展开 View 依赖；旧血缘图继续限制为 Paimon 表，避免内部 View 被按 Paimon 范围展示。
- 真实验证修复 MySQL JSON 格式规范化导致的相同字段契约误判；角色范围更新先 flush 删除，再插入保留范围，修复部分撤权的唯一键冲突。
